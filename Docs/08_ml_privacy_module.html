ML & Privacy Module: System Design & Specs

Transforms raw DOM trees and screenshot data into a privacy-safe, semantically actionable context for the remote AI planner. All raw PII and anonymization lookup mappings strictly remain local to the user's browser sandbox.
🛡️ Local Privacy Firewall 🔍 PaddleOCR.js / PP-OCRv5 👁️ YOLO26n ONNX 🧠 BERT-base NER ⚡ Web Worker + WebGPU 🔒 Zero Server Leakage
⚠️ Non-Negotiable Security Property
The remote server agent receives enough semantic information to perform autonomous browser reasoning (element roles, visible non-sensitive labels, normalized bounding boxes, and consistent session pseudonyms), but it must NEVER receive the actual sensitive value or the browser-local mapping that could recover it. All sanitization, OCR, visual masking, and token generation execute 100% locally.
🛡️
Chapter 01

Scope of the Local Privacy Firewall

The ML & Privacy module acts as a local client-side privacy firewall. It sits directly between the webpage execution environment and the remote AI agent, completely owning perception, PII detection, privacy fusion, anonymization, visual/text redaction, session identity management, and sanitized-context delivery. 

RAW WEBPAGE (Live DOM Tree + Screen Pixels)
│
▼
LOCAL PRIVACY FIREWALL (Client-Side Extension / Web Worker Sandbox)
├── DOM Analyzer              Semantic HTML signals, labels, input types, autocomplete, ARIA, bboxes
├── PaddleOCR.js / PP-OCRv5   Character extraction, word polygons, recognition confidence
├── YOLO26n ONNX (WebGPU)     Visual detection: FACE, ID_CARD, PASSPORT, CREDIT_CARD, SIGNATURE, QR/BARCODE
├── BERT-base NER (ONNX)      Contextual named entities: PERSON, LOCATION, ORGANIZATION
├── Structured PII Rules      Verhoeff/Luhn checksums, PAN/GSTIN modulo, Email/Phone regex
├── Entity Resolver           Spatial IoU fusion & multi-source confidence weighting
├── Session Manager           Stable anonymous identities ([PERSON_A71C], crypto.getRandomValues)
├── Semantic Anonymizer       Surgical text span rewriting preserving page reasoning layout
├── Visual Redactor           Irreversible canvas pixel masking with 15% safety padding
└── Sanitized Context Builder Compact JSON schema wire payload (elements + pseudonyms)
│
▼
FINAL PRIVACY GATE (Fail-Closed Outbound Audit Barrier)
├── Blocks: Raw DOM [X], Raw OCR [X], Raw PII [X], Session Mapping Vault [X]
└── Allows: Redacted Screenshot WebP + Sanitized Semantic JSON Payload
│
▼
SERVER AI AGENT (Private Intranet / Cloud VLM)
└── Reasons over [PERSON_A71C], element roles, and masked screenshot → returns action JSON (CLICK, TYPE, SCROLL)
💡
Operating Principle: Fail-Closed If any detection step encounters an error, if hardware resource limits are exceeded, or if the privacy gate detects a questionable span, transmission halts immediately. The system defaults to masking rather than risking un-anonymized data egress.

Chapter 03

Multi-Modal Perception Layer

Visual and structural perception are synthesized across four specialized detectors, handling everything from explicit DOM attributes to scanned PDF text and non-text visual identity cards.

DOM Analyzer & Semantic HTML Feature 1

The DOM analyzer is the first-response signal because HTML source code often explicitly identifies sensitive fields even when visual models are ambiguous.

HTML Signals → Normalized Detection Mapping HTML → JSON 
<!-- Sample Input Elements on Webpage -->
<input type="password" autocomplete="current-password">
<label>Email</label><input type="text">

/* Emitted Normalized Detection Objects */
[
  { "type": "PASSWORD", "confidence": 0.99, "bbox": [120, 240, 380, 276] },
  { "type": "EMAIL",    "confidence": 0.95, "bbox": [120, 180, 380, 216] }
]
  • Inspects type, name, id, placeholder, aria-label, autocomplete, and nearby semantic label contexts.
  • Extracts bounding boxes via getBoundingClientRect() with viewport scroll normalization.
  • Filters out irrelevant hidden nodes (display: none, visibility: hidden, zero dimensions).
  • Uses debounced MutationObserver to continuously re-evaluate dynamic SPAs (React/Vue/Angular).
PaddleOCR.js / PP-OCRv5 Feature 2

PaddleOCR is the primary optical character recognition engine. Running locally in WebAssembly/WebGPU, it supplies the text geometry needed to connect OCR output to downstream PII detection and visual redaction. 

Screenshot → PaddleOCR.js → text + polygon/bbox + confidence → PII rules / BERT NER → sensitive text spans → redaction + semantic labels
  • Outputs 4-point polygon bounding geometry for rotated text and axis-aligned bounding boxes for inline text.
  • Supports multi-lingual recognition across English and Devanagari numerals/scripts found on Indian official documents.
YOLO26n Privacy Detector Feature 3

YOLO26n provides visual detection of privacy-sensitive objects that OCR and DOM analysis cannot reliably identify.

FACE
CV-01
Human portrait photos on user profiles, ID cards, video call previews, and uploaded document thumbnails.
ID / PASSPORT
CV-02
Physical government IDs, Aadhaar cards, passport bio pages, and employee badges displayed on screen.
CREDIT_CARD
CV-03
Payment cards showing card numbers, expiration dates, bank logos, and EMV security chips.
SIGNATURE
CV-04
Handwritten cursive signatures on legal contracts, official letters, checks, and application forms.
QR / BARCODE
CV-05
UPI payment QR codes, 2D Aadhaar secure QRs, document barcodes, and boarding pass strips.
DRIVER_LICENSE
CV-06
State driving permits displaying license numbers, driver biometric photos, and residential addresses.
  • Fine-tuned on privacy-specific datasets and exported to ONNX for browser execution.
  • Starts with an FP32 browser baseline, benchmarked down to FP16 and INT8 for low-latency WebGPU passes.
  • Applies automatic 15–20% conservative padding around high-risk bounding boxes before redaction.
BERT-base NER (Contextual Entities) Feature 4

BERT-base NER supplies contextual understanding for entities such as PERSON, LOCATION, and ORGANIZATION. It complements deterministic PII rules rather than replacing them. 

OCR Text: "John Smith lives in New Delhi"
      │
      ▼
BERT-base NER
      ├── PERSON: John Smith
      └── LOCATION: New Delhi
      │
      ▼
Map Token Spans → OCR Bounding Boxes → Emitted Privacy Entities

Layered PII Detection & Spatial Fusion

PRATYAKSHA avoids single-point-of-failure perception by layering deterministic rules, algorithmic validators, and neural NER models into a unified geometric fusion algorithm.

3-Tier Layered PII Architecture Feature 5
Layer Covered Entity Types Verification Mechanism Confidence
1. DOM Semantic Rules PASSWORD, EMAIL, PHONE, OTP, payment fields, credentials HTML attributes, autocomplete types, label proximity 0.95 – 0.99
2. Regex & Validation EMAIL, PHONE, PAN, AADHAAR, CREDIT_CARD, IP/URL Verhoeff checksum, Luhn algorithm, Modulo-36 check 0.999 (Checksum)
3. BERT-base NER PERSON, LOCATION, ORGANIZATION, contextual names Subword token classification embeddings 0.85 – 0.98

Evidence Combination: Combine evidence across all layers instead of relying on a single detector.

Entity Resolver & Privacy Fusion Feature 6

The same sensitive entity may be detected by multiple components. The resolver merges these detections using geometry, type compatibility, text similarity, and confidence.

Chapter 05

Cryptographic Anonymization & Visual Redaction

Replaces sensitive personal values with session-stable semantic identifiers while permanently obliterating underlying pixels before any byte leaves the client workstation.

Session Manager (Stable Identity) Feature 7

The session manager creates stable, random semantic identities. Stability matters because the remote agent may observe the same entity over multiple agent iterations.

Local Mapping Vault vs. Server Egress View JavaScript In-Memory Vault 
/* 🔒 LOCAL BROWSER MAPPING (NEVER LEAVES DEVICE) */
PERSON: John Smith       → [PERSON_A71C]
EMAIL: john@gmail.com    → [EMAIL_92F4]
PHONE: +919876543210     → [PHONE_C821]

/* 🌐 SERVER SEES (SERVER NEVER SEES THE MAPPING): */
[PERSON_A71C], [EMAIL_92F4], [PHONE_C821]
  • Use crypto.getRandomValues() for unpredictable pseudonym identifiers.
  • Normalize entity values before lookup to prevent duplicate tokens.
  • Keep a stable token for the same entity during a session; never reuse a token for another entity.
  • Provide clean session reset/expiry; do not log raw values or mappings.
Semantic Anonymizer Feature 8

The semantic anonymizer preserves meaning while removing the private value, replacing only sensitive spans and keeping public UI text, labels, ordering, and layout so the agent can still reason about the page.

Original Text (Sensitive Data) Sanitized Representation (Sent to AI)
Welcome John Smith Welcome [PERSON_A71C]
Email: john.smith@gmail.com Email: [EMAIL_92F4]
Phone: +91 9876543210 Phone: [PHONE_C821]
Visual Redactor Feature 9

Applies irreversible visual masking to screenshot pixels locally before network transmission:

FACE
BLUR / MASK
Heavy Gaussian blur, pixelation, or opaque box overlay.
PASSWORD / SECRET
OPAQUE MASK
Solid opaque rectangle permanently destroying underlying pixel values.
CARDS / ID / SIGNATURE
PADDED MASK
Opaque charcoal mask with mandatory 15% safety boundary padding.
QR / BARCODE

Complete wipe covering the entire optical code region and margin.

Chapter 06

Fail-Closed Privacy Gate & Web Workers

Guarantees zero main-thread UI jank and establishes an unyielding audit barrier that blocks data egress if any sensitive span remains unmasked.

Sanitized Context Builder (JSON Schema) Feature 10
Sanitized Context Payload Wire Contract JSON Schema 
{
  "session_id": "opaque-id",
  "screen": { "width": 1440, "height": 900 },
  "elements": [
    { "id": "btn_submit", "role": "button", "label": "Submit Form", "bbox": [600, 700, 750, 740] }
  ],
  "entities": [
    { "type": "PERSON", "label": "[PERSON_A71C]", "bbox": [100, 150, 250, 180] }
  ],
  "screenshot": "<sanitized image blob>"
}

Retains actionable UI semantics (roles, non-sensitive labels, element geometry, page state, sanitized entities) while avoiding raw DOM transmission.

Final Privacy Gate (Fail-Closed Barrier) Feature 11 
Raw DOM         ■■■■■■■■■■■■■■■■ X (BLOCKED)
Raw OCR         ■■■■■■■■■■■■■■■■ X (BLOCKED)
Raw PII         ■■■■■■■■■■■■■■■■ X (BLOCKED)
Session Mapping ■■■■■■■■■■■■■■■■ X (BLOCKED)

Sanitized screenshot + sanitized DOM + semantic entities
      │
      ▼
PRIVACY AUDIT → PASS → NETWORK SEND
             → FAIL → FAIL CLOSED (ABORT)
  • Check for raw sensitive spans before serialization.
  • Ensure every high-risk visual entity has an opaque mask.
  • Ensure session mapping dictionary is never serialized.
  • Fail closed if privacy analysis is incomplete.
  • Optionally run post-redaction OCR during evaluation to prove zero leakage.

Keeps heavy local ML inference completely off the page's main execution path, maintaining a buttery-smooth 60 FPS.
